# 赛狐全店铺广告监控与调控建议

这套程序读取赛狐开放平台的 Amazon SP 广告数据，保存本地快照，并生成监控 Excel 和调控建议。当前版本只读，不会修改广告预算、竞价或状态。

## 当前范围

- 自动分页发现全部“广告已授权且状态正常”的 Amazon 店铺。
- SP 广告活动、关键词和商品投放基础数据。
- SP 广告商品位置与在线产品上架时间，按每个广告 SKU 展示新品状态。
- SP 活动日报与投放日报异步批量下载；默认读取最近 14 个成熟日（截至 D-2）。
- 独立 SP 活动小时层按分级队列轮转读取当日暂定数据，只做预警、阻断和复核确认。
- 活动级预算建议，以及可唯一关联基础竞价的关键词/商品投放数值建议。
- 多店铺、多站点和多币种隔离；不同币种金额绝不直接相加。
- SQLite 历史快照、原始 XLSX、CSV 建议清单、Excel 工作簿、网页数据和接口日志。

接口依据：

- [SP 广告活动](https://sellfoxapi.apifox.cn/api-367482273)
- [SP 关键词投放](https://sellfoxapi.apifox.cn/api-367482278)
- [获取店铺列表](https://sellfoxapi.apifox.cn/api-51516635)
- [创建广告日报下载任务](https://sellfoxapi.apifox.cn/api-52365899)
- [查询广告日报下载任务](https://sellfoxapi.apifox.cn/api-52365898)
- [SP 商品投放](https://sellfoxapi.apifox.cn/api-367482279)

SB、SD、搜索词否词建议、自动执行调控不在第一版范围内。

## 首次配置

1. 默认配置已经开启自动店铺发现，无需手工维护店铺 ID：

```json
"shops": [],
"collection": {
  "discover_shops": true,
  "lookback_days": 14,
  "maturity_lag_days": 2,
  "max_campaigns_per_shop": 0,
  "listing_new_days": 90,
  "report_shop_batch_size": 50
}
```

程序只纳入 `adStatus=auth` 且 `status=0` 的店铺，并根据 Amazon `marketplaceId` 确定币种。`max_campaigns_per_shop=0` 表示不截断启用活动。若出现未知站点、重复店铺名或无法确定币种，程序会安全退出而不是猜测。

2. API 凭据沿用订单导入程序的 Windows DPAPI 加密配置，不写入代码或 JSON。手动临时测试时，也可以只给当前 PowerShell 会话设置环境变量：

```powershell
$env:SELLFOX_CLIENT_ID = "你的 client_id"
$env:SELLFOX_CLIENT_SECRET = "你的 client_secret"
```

如果尚未保存过凭据，可运行：

```powershell
& '.\.venv\Scripts\python.exe' '.\sellfox_import.py' --configure
```

每日计划任务不会继承上面临时设置的 `$env:` 变量，因此定时运行必须先用 `--configure` 保存 DPAPI 配置，并由同一个 Windows 用户创建任务。

## 运行

双击 `手动运行广告监控.bat`，或执行：

```powershell
& '.\.venv\Scripts\python.exe' '.\sellfox_ads_monitor.py' --once
```

临时只测试单个店铺时仍可显式指定店铺和币种，例如：

```powershell
& '.\.venv\Scripts\python.exe' '.\sellfox_ads_monitor.py' --once `
  --shop-id 123456 --currency USD
```

`生成广告监控演示.bat` 只用于界面演示。网页同步和正式监控会拒绝把 demo payload 覆盖到真实看板。

## SKU 上新判定

新品只按在线产品 V2 的 `openDate`（上架时间）判断，不使用第一次销售时间或第一次出单时间。默认规则为：

- 开售 0–90 天：`新品`。
- 开售超过 90 天：`老品`。
- 上架时间缺失、日期在未来、数据源失败或无法唯一匹配：`未知`。

关联键为 `店铺 ID + ASIN + SKU`。ASIN 会统一转大写，SKU 保留精确值；重复匹配不会猜测。在线产品读取 `active + inActive`，排除历史删除记录。阈值可通过 `collection.listing_new_days` 调整。

网页的“SKU上新”页按当前启用 SP 活动的每个广告商品位置逐行显示活动 ID、广告组 ID、adId、SKU、ASIN、上架日期和上架天数，支持店铺、关键词和新品状态筛选，每页 10 条。父活动并非启用状态的历史广告位置不进入页面，但排除数量会保留在覆盖统计中。调控建议、实时异常和活动概览也支持按 `新上架 / 非新品 / 混合 / 未知` 筛选。

新品或混合活动只进入观察/人工复核；生命周期未知时阻断进入执行确认。监控采集本身只读，调控面板只有在人工二次确认后才会执行修改。

## 广告表现与预算状态

广告表现只对老品活动判断，使用最近 7 个完整成熟日：至少 7 个成熟日且点击不少于 10 次后，`CTR = 点击量 / 展示量`、`购买率 = 订单量 / 点击量`。CTR 不低于 1% 且购买率不低于 10% 为“表现正常”，任一未达标为“表现不好”；未达到样本门槛单独显示“样本不足”。新品显示“新品观察”，混合或日期无法匹配的活动不自动判好坏。

“预算跑满”统一为完整日花费达到日预算 98%，或 Amazon 明确返回 `OUT_OF_BUDGET`。近 7 天跑满状态与广告表现组合成以下动作矩阵：

| 广告表现 | 预算状态 | 结论 |
|---|---|---|
| 正常 | 已跑满 | 理想状态；利润和库存通过后才可评估加预算 |
| 正常 | 未跑满 | 不加预算；检查竞价、广告位、关键词覆盖和流量获取 |
| 不好 | 已跑满 | 最高优先级；禁止加预算，先降竞价并清理差词和低效投放 |
| 不好 | 未跑满 | 保持不跑满，继续优化原因，不强行扩量 |
| 新品观察 | 任意 | 进入新品诊断和人工复核 |

活动详情同时显示自动、精准、广泛、词组、手动混合或商品投放，并前置展示固定竞价、动态竞价（只降低）、动态竞价（提高和降低）及广告位加价比例。多个 SKU 使用同一活动时会明确提示共享预算且非平均分配。

调控审计记录对象、操作时间、操作类型、原值和新值。页面以调整日为锚点比较前后各 7 个完整成熟日的展示、点击、CTR、花费、CPC、订单、购买率、销售额、ACoS、ROAS 和跑满天数；后 7 天未成熟时只显示进度，不提前下结论。竞品图片吸引力、顶部差评和实际广告排名仍属于人工检查项，不自动推断。

默认输出：

- `outputs/ads_monitor/<multi-范围编号>/赛狐广告监控与调控建议.xlsx`
- `outputs/ads_monitor/<multi-范围编号>/sellfox_ads_recommendations.csv`
- `outputs/ads_monitor/<multi-范围编号>/sellfox_ads_monitor_payload.json`
- `ads-monitor-web/public/data/ads-monitor.json`（网页当前 live 数据）
- `data/sellfox_ads.sqlite3`
- `data/ads_report_cache/`（当日基础数据缓存与原始日报）
- `%LOCALAPPDATA%/SellfoxTK/logs/sellfox_ads_monitor.log`

## 广告诊断持久化快照

诊断页默认优先读取 `data/ad_diagnostic_snapshots/`，不再在每次打开或切换活动时等待整套赛狐接口。快照按店铺和活动分片，活动列表、总览和完整详情分别原子替换；刷新失败时保留该店铺、该活动上一次成功版本。

每轮任务会从赛狐动态发现全部广告已授权且状态正常的 Amazon 店铺，并刷新这些店铺的全部启用 SP 活动清单，以及诊断页使用的广告结构、Listing、经营上下文、当前小时和成熟报表内容。它不会抓取与诊断无关的接口或保存买家敏感字段。单个店铺失败不会中断其他店铺，结果会记录为部分失败。

默认有效期为 60 分钟。过期后页面先展示旧快照并标记时效，同时在后台合并刷新；总览和完整详情共用一次刷新任务。

由于当前授权站点数量和启用活动较多，定时任务不会在一轮内执行数千次深度报表读取。每 60 分钟并发更新全部授权店铺的活动清单，并为每个有广告活动的店铺预热默认活动的首屏 overview 快照；无活动店铺保留空目录快照，不请求无意义的详情。完整成熟报表与活动详情默认每轮仅在有活动的店铺中选择 8 个最久未处理的店铺、每店 1 个最旧活动进行轮转。21号站-李娜-US 的默认活动会在每轮结束后额外优先刷新，确保它每小时都有可直接读取的完整快照；优先店铺和活动可通过运行脚本的 `-PriorityShopId`、`-PriorityCampaignId` 参数调整。用户实际打开的其他活动会立即生成并持久化 overview 快照，后续访问直接命中。首次使用先在本机终端安全录入两项赛狐 API 凭据（密钥不会显示，也不要发送到聊天）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\配置赛狐广告凭据.ps1'
```

安装每 60 分钟自动刷新全部授权店铺的任务：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\install_ads_diagnostic_hourly_task.ps1'
```

单轮活动数可在安全上限内调整，例如 `--batch-size 12`；允许范围为 1～25。快照任务与成熟层、实时层共用 `Global\SellfoxAdsMonitor` 进程互斥锁，避免同时争抢赛狐接口。轮转状态保存在 `batch-state.json`，页面触发和定时任务都只覆盖对应的成功分片。

诊断服务可通过启动参数调整快照行为：

```powershell
python '.\sellfox_ad_diagnostic_server.py' `
  --snapshot-ttl-minutes 60
```

仅排障时可加 `--no-snapshot` 恢复逐请求读取；日常使用不建议关闭。

## 双时间层

成熟归因层与实时层完全分开：

| 层级 | 数据窗口 | 用途 | 是否直接调价 |
|---|---|---|---|
| 成熟归因层 | 最近 14 个成熟日，截至 D-2 | 生成正式调控候选 | 否，仍需人工审核 |
| 实时监控层 | 各站点当日已完成小时 | 异常预警、阻断错误扩量、执行前复核 | 否 |

实时层不会写入 `data/sellfox_ads.sqlite3`，也不会改动成熟层建议。它使用独立的：

- `sellfox_ads_realtime.py`
- `data/ads_realtime_state.json`
- `ads-monitor-web/public/data/ads-realtime.json`
- `%LOCALAPPDATA%/SellfoxTK/logs/sellfox_ads_realtime.log`

赛狐小时活动接口要求逐活动请求，不能用一次请求拉取全部店铺。默认每轮最多 350 次只读调用，每 15 分钟运行一轮，并按以下频率持久化轮转：

- P0：人工关注活动，30 分钟。
- P1：成熟层可执行候选、新品、每店最高花费活动，2 小时。
- P2：其他有花费活动，4 小时。
- P3：零花费或低活跃活动，12 小时。

页面会显示实际店铺/活动覆盖、积压、失败和观测时间；部分覆盖绝不显示成“全部正常”。当日订单、销售额和 ACoS 都属于暂定数据，`0 单`只会触发观察，不会直接产生降价动作。新品异常同样优先观察，避免在学习期机械降价。

站点日期按 Amazon marketplace 时区映射计算。赛狐响应没有广告账户时区字段，因此可以在 `ads_monitor_config.json` 的 `realtime.timezone_by_shop` 中按店铺覆盖默认时区；未知时区会停止该店实时判断，不会猜测日期。

手动运行：

```powershell
& '.\.venv\Scripts\python.exe' '.\sellfox_ads_realtime.py'
```

只查看本轮计划、不访问 API：

```powershell
& '.\.venv\Scripts\python.exe' '.\sellfox_ads_realtime.py' --plan-only
```

安装每 15 分钟自动运行的只读任务：

```powershell
& '.\安装广告实时监控任务.ps1'
```

计划任务与成熟层共用进程互斥锁；每天成熟层正在采集时，实时任务会安全退出并在下一轮重试，避免同时争抢赛狐接口限额。

## 每天 09:00 自动运行

用 PowerShell 执行一次安装脚本：

```powershell
& '.\安装广告监控每日任务.ps1'
```

安装脚本会强制检查当前 Windows 用户保存的 DPAPI 凭据、Access Token 和全店铺发现；只有预检通过才创建 `SellfoxAdsMonitorDaily`。每日任务优先保证网页更新，因此使用 `--no-workbook`，并把过程 JSON/CSV 写入独立的 `outputs/ads_monitor_scheduled/`，不会让手动生成的 Excel 与每日网页数据混淆；需要 Excel 时可手动运行。任务支持错过 09:00 后补跑、睡眠唤醒和失败重试，但当前 Windows 用户必须保持登录；若用户上下文改变，DPAPI 配置需要在该用户下重新保存。首次全店铺基础数据读取会比后续同日重跑更久。

## 默认建议规则

| 场景 | 默认门槛 | 建议 |
|---|---|---|
| 高 ACoS | 订单不少于 3，且 ACoS 高于目标值 20% | 竞价降低 10% |
| 低 ACoS | 订单不少于 5，且 ACoS 低于目标值 20% | 竞价提高 5% |
| 有花费无订单 | 点击不少于 10，花费不少于 20 | 竞价降低 10% |
| 盈利且预算受限 | 老品、CTR 与购买率双达标，近 7 天至少 3 天预算利用率达到 98% | 利润和库存通过后，预算提高 10% |

所有比例和门槛都在 `ads_monitor_config.json` 中调整。店铺也可以单独覆盖 `rules`。

## 数据安全门禁

以下情况只显示“观察/阻断”，不产生可执行建议：

- 接口只返回部分数据、异步任务失败或有请求失败。
- 活动日报与投放日报的花费、销售额或订单无法对账；此时只阻断受影响活动的投放级建议。
- 活动或投放对象不是启用状态。
- 明确处于暂停、归档、停用或不合格的投放状态。
- 关键 ID、币种、日期或指标缺失。
- 点击大于曝光，或曝光、点击、花费、销售、订单出现负数。
- 最新数据没有到达预期成熟日 D-2。
- 成熟数据天数、点击、花费或订单样本不足。
- 活动或投放对象处于保护名单。

统计窗口默认避开最近 2 天，降低 Amazon 广告归因回补造成的误判。Excel 中的建议必须先人工复核；第一版不会自动执行。

同一天重复运行时，程序先写入临时批次，采集和建议生成完成后再原子替换；若重跑中断，上一次成功结果仍会保留。

## 第一版已知限制

- 赛狐官方没有承诺下载 XLSX 的列名契约；程序会严格校验实测表头，表头变化时安全报错，不会错列导入。
- 调控审计只跟踪通过本系统执行的调整；在 Amazon 或其他工具中直接修改的记录不会自动进入前后 7 天复盘。
- 商品投放基础竞价已接入；无法与基础对象唯一关联时仍只提示人工复核。
- SB、SD、搜索词否词、广告位和自动写回可在第二版接入。
